`wayloop validate` now checks council reports, living specifications and change deltas against
their published schemas. A living specification is checked in its normalised form, the YAML or
JSON document its Markdown file stands for; the Markdown file itself is not read yet. Each
refusal names the faulty field and why: a status the type does not have, such as `published`
for a living specification, with the statuses it accepts; an acceptance criterion verified by a
judge without a rubric; an operation of a change delta without the requirement, the text or the
name its kind needs; a question of a council report with fewer than two options; or a capability
that is not lower-case words joined by hyphens, with the corrected value when one can be
derived. Whether the linked brief or specification exists, whether a part is unique, whether a
recommendation or an answer is one of the options and whether a change touches each
requirement once are not checked yet: the result lists these checks as not done. An operation
of a change delta that carries a member its kind refuses (a requirement on `added`, a text on
`removed` or `renamed`, a name on `removed`) is not refused yet either.
