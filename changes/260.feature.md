`wayloop validate` now checks hand-overs in both their forms: the input an agent submits at the
end of a session, marked with `input_kind: handover_input`, and the record the engine writes
from it. The input holds only what the agent writes (the step reached, the files touched, the
work left, the open questions, the rulings and the next step); a field that only the engine
fills, such as `tokens`, is refused with the field named, and every error of an input carries
the code `handover_input`. The step is one of the nine steps of the issue cycle, spelt in
`snake_case`, for example `counter_review`; a spelling such as `counter-review` is refused with
the nine accepted values. The schemas are published as `schemas/artifacts/handover/v1.json`
(record) and `schemas/artifacts/handover/v1.input.json` (input). Whether the issue and the task
of a record exist, and whether its branch follows the naming rules, are not checked yet: the
result lists these checks as not done.
