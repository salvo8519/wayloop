`wayloop validate` now checks the branch of each pull request and the header of each commit,
and the title of each pull request as a header. A branch must be `<type>/<issue>-<slug>` or
`sprint/S<NN>/<issue>-<slug>`, with an issue number within the range of an issue number, a slug
of at most five words and at most 100 characters in all; Dependabot, release and revert branches
are exempt. A header must be `<type>(<scope>)[!]: <subject>`, with a type and a scope of the
policy, a subject that starts with a lower-case letter and has no final full stop, and at most
72 characters. A commit that marks a breaking change with `!` needs a `BREAKING CHANGE:`
paragraph or footer in its body. Headers that git writes itself (`Merge `, `Revert "`,
`fixup! `, `squash! `) are exempt. Errors carry the accepted types or scopes in `expected`, and
the corrected branch or header in `fix` when one can be derived and breaks no other rule.

The policy is now bounded: at most 32 types, 256 scopes and 256 areas, each name one lower-case
word of letters, digits and hyphens that starts with a letter; a policy outside these bounds is
refused as a command input. The `area` of epics and tasks and the `commit_scope` of
specifications have the same form.

The check `naming`, listed as not done until now, is replaced by `branch_name` and
`commit_header`, which run, and `pull_request_link`, the check of the issue links of a pull
request, which is still listed as not done.
